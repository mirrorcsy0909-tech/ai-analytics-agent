# Streamlit 会话与图表修复

日期：2026-10-18。

## 修复的行为

原页面全局缓存带检查点的工作流，“清空对话”只换会话编号；底部图表
扫描整个 `outputs/`，会把旧测试图或另一会话的图显示出来。

现在第一次分析才为当前浏览器会话建立工作流，并在该会话内复用。
新问题保留消息上下文；中断重试仍继续原检查点。不同浏览器会话各自
拥有工作流。点击 **Clear conversation** 会移除当前会话对工作流的
引用，同时清空答案、指标、错误、输入和图表，不影响另一会话。

图表只接受本次结果的 `artifacts` 与成功工具证据共同声明的 PNG。
捕获前核对输出目录范围、文件类型、大小和 SHA-256，拒绝软链接、
缺失、外部或被替换的文件。页面保存核对后的图像字节；后台文件
随后被移走或覆盖，不会悄悄改变已显示的图。无法核对时显示重新
生成提示，而不是让整个分析页面报错。

每个会话最多保留最近四张不同图，每张最多 5 MB。图表快照总大小
最多 20 MB；这不包含工作流、消息和其他页面状态的内存。

会话保存在进程内存，刷新网页或重启服务会丢失。清空页面不删除
磁盘上的 PNG 或本地指标文件，也不撤回已经提交的远程追踪。
本次没有增加账户系统、公共部署或持久会话服务。

## 验证

完整离线测试 **103/103 通过**，没有调用模型或上传数据。新增七项
回归检查覆盖：

- 两个真实 Streamlit AppTest 会话分别创建工作流；清空一个后，另一个
  仍用自己的检查点继续。
- 图表只出现在所属会话；清空后消失；原文件删除后已捕获的图仍可展示。
- 工作流创建失败后可再次提交，不错误地提供检查点恢复。
- 成功工具证据与图表列表必须匹配；篡改、缺失、外部路径、软链接、
  无效 PNG 和超大文件被拒绝；历史按最近顺序去重并限制为四张。

原 19 场景 / 25 轮模型验收记录保持不变。本次更改网页的状态和图表
展示，没有重新运行该模型验收，不能把归档结果称为本次的新模型测试。

复测命令：

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -v
```

实现采用 [Streamlit Session State](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.session_state)。
[缓存文档](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.cache_resource)
说明了默认全局资源跨会话共享的行为；本实现使用会话状态保存工作流，
不依赖较新版本才支持的缓存作用域参数。
